# Кейс 1. Data-Driven Curriculum - каким должен быть проект

## 1. Кто пользователь и какое решение он принимает

**Методист школы / отдела образования.** Раз в четверть он решает три вопроса:

1. Какие темы программы ученики не усвоили и почему (какое задание, какая типичная ошибка)?
2. Какой учебник работает лучше - и можно ли это утверждать, если учебник и учитель «склеены»?
3. Сколько часов дать каждой теме в следующем периоде, не выходя за сетку часов?

Значит, продукт - это **рабочее место методиста**, а не приложение для ученика.
Тренажёр ученика остаётся вспомогательным: это пример источника живых данных.

## 2. Критерии жюри и что им должно соответствовать

| Критерий | Что должно быть в продукте |
|---|---|
| Соответствие задаче (4 функции кейса) | Отдельные экраны: «Темы», «Учебники», «Часы» + «Обзор» со сводкой решений |
| Обоснованность (data-driven) | Каждая рекомендация показывает цифру, из которой выведена: доля не освоивших, ДИ, n |
| Корректность аналитики | Учёт учителя при сравнении учебников, интервалы, пометка «мало данных», блокировка вывода при смешении |
| Практическая ценность | Сетка часов «было → стало», экспорт плана, отчёт для педсовета на одну страницу |
| Работа с реальными данными | Импорт CSV с валидацией, шаблон, программа часов редактируется |
| UX / UI | Понятная навигация, фильтры, плавные анимации, тёмная тема, мобильная версия |
| Демонстрация | Реалистичные демо-данные: 6 классов, 3 учителя, 3 учебника, 2 предмета, разные результаты |

## 3. Структура продукта

```
Обзор      KPI → топ проблемных тем → лучший/худший учебник → изменения часов → «решения для педсовета»
Темы       тепловая карта тема × класс → панель темы: задания, трудность, различающая способность,
           частые неверные ответы (дистракторы), сравнение классов
Учебники   матрица «учитель × учебник» (проверка смешения) → скорректированная разница прироста
           с 95% ДИ (общая и по каждой теме) → вердикт и что исправить, если вывод невозможен
Часы       программа часов (редактируется) + резерв + перенос с освоенных тем
           → рекомендация «было → стало» с причиной по каждой теме → экспорт CSV
Отчёт      одна страница для печати / PDF
Данные     импорт / экспорт CSV, шаблон, качество данных, живые ответы из тренажёра
```

## 4. Методика (что считаем и почему)

* **Освоение темы.** Для ученика: доля верных ответов по теме. Тема освоена, если ≥ порога (по умолчанию 70%, меняется).
  Для темы: средний результат учеников и **доля не освоивших** - именно она, а не средний балл, задаёт потребность в часах.
* **Надёжность.** Меньше 10 учеников или 30 ответов → «мало данных», ячейка штрихуется, рекомендации помечаются.
* **Анализ заданий.** Доля верных (трудность), точечно-бисериальная корреляция с остальным тестом (различает ли задание
  сильных и слабых), самый частый неверный ответ - это типичная ошибка, которую методист разбирает с учителями.
* **Сравнение учебников.** Прирост ученика = результат − входная диагностика. Модель `прирост ~ учебник + учитель (+ тема)`
  методом наименьших квадратов: разница учебников оценивается *внутри* учителей. Если граф «учитель-учебник» несвязен
  (учебник используется только у «своего» учителя), вывод блокируется и система подсказывает, какой класс перевести.
  95% ДИ - бутстрэп по ученикам внутри классов. Вывод «связан с большим приростом», а не «вызывает».
  Значимо практически: |разница| ≥ 5 п.п. и ДИ не пересекает 0.
* **Часы.** Сетка программы сохраняется. Дополнительные часы = резерв + (по желанию) до 20% часов освоенных тем
  (≥ 85% учеников освоили). Распределяются пропорционально «недоосвоенным часам» = доля не освоивших × часы темы,
  не больше +50% к теме, целые часы методом наибольших остатков. Сумма часов всегда сходится.

## 5. Что было не так в исходной версии и что исправлено

| Было | Стало |
|---|---|
| Математика и казахский - одни и те же числа с разными подписями | Отдельная генерация для каждого предмета, свои темы, задания, ошибки |
| 1-е классы решают дроби и вероятность | 6-е классы, темы по программе 6 класса |
| Даты ответов случайны по всей четверти | Каждая тема - контрольная в свою неделю, входная диагностика в начале |
| Сравнение только 2 учебников, только по одной теме | 3 учебника, общий эффект + матрица учебник × тема |
| Часы - только «резерв 8 занятий» без программы | Сетка программы, было → стало, перенос часов, причины, экспорт |
| ДИ без учёта структуры | Бутстрэп внутри классов + явное предупреждение о числе классов |
| Плашка «Демо-данные» и после загрузки CSV | Источник данных показывается честно |
| Приложение ученика по умолчанию, методист «добавкой» | Рабочее место методиста по умолчанию, тренажёр - источник данных |

## 6. Ограничения (говорим жюри честно)

* Данные демо синтетические, это явно подписано.
* Хранение - в браузере, без сервера и учётных записей (для пилота нужен бэкенд и роли).
* Сравнение учебников наблюдательное: случайного распределения классов нет, поэтому причинность не утверждается.
